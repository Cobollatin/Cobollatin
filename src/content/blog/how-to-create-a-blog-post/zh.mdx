本项目使用 **Astro Content Collections** 驱动博客。文章放在 `src/content/blog/`，并由 `src/pages/blog/`（默认语言）与 `src/pages/[lang]/blog/`（带语言前缀的路由）渲染。

## 1) 创建新文章（推荐：使用脚手架脚本）

要一次性创建包含所有支持语言文件的文章目录，运行：

```bash
bun run new:post <slug> "可选标题"
```

该命令会在 `src/content/blog/<slug>/` 下生成每个 locale 对应的 `.mdx` 文件（见 `src/i18n/locales.ts`）。

如果你想手动创建：先创建以文章 slug 命名的文件夹（该文件夹名就是 URL slug），再在其中添加 `zh.mdx`（以及其他语言文件）：

- 文件：`src/content/blog/my-new-post/zh.mdx`
- URL（中文）：`/zh/blog/my-new-post/`

## 2) Frontmatter（必填字段）

每篇文章都必须包含符合 `src/content.config.ts` 中 blog collection schema 的 frontmatter。

最小必填示例：

```yaml
---
title: '我的新文章'
description: '用于列表、预览与 SEO 的一句话摘要。'
pubDate: '2026-02-02'
lang: 'zh'
---
```

可选（推荐）字段：

- `heroImage`：图片路径（通常来自 `public/`）
- `keywords`：字符串数组，用于筛选与搜索
- `updatedDate`：显示“最后更新于 …”

包含全部字段的例子：

```yaml
---
title: '我的新文章'
description: '用于列表、预览与 SEO 的一句话摘要。'
pubDate: '2026-02-02'
updatedDate: '2026-02-10'
heroImage: '/blog-placeholder-1.jpg'
keywords: ['astro', 'content collections', 'writing']
lang: 'zh'
---
```

## 3) 编写正文内容

可以使用 Markdown（或 MDX）。标题会自动生成可链接的锚点，配置来自 `astro.config.ts` 中的 rehype 插件。

## 4) i18n：添加同一篇文章的翻译

本项目支持的 locales 定义在 `src/i18n/locales.ts`：

- `en`（默认）
- `es`, `zh`, `ja`, `ru`

### 博客翻译如何分组

同一篇文章的不同语言版本通过 **translation key** 分组，该 key 来自 `src/content/blog/` 内的第一个路径片段（也就是文件夹名）。

因此，只要文件夹名相同，就会被认为是同一篇文章的翻译版本：

- `src/content/blog/my-new-post/en.mdx`（`lang: 'en'`）
- `src/content/blog/my-new-post/zh.mdx`（`lang: 'zh'`）

对应 URL：

- 英语：`/blog/my-new-post/`
- 中文：`/zh/blog/my-new-post/`

如果某个 locale 缺少翻译，会回退到默认语言内容。

### 强制“每个语言都有文件”

如果你想强制每篇文章都包含所有 locale 的文件，运行：

```bash
bun run check:i18n
```

## 5) 本地化路由（页面如何生成）

- 默认语言（无前缀）：`src/pages/blog/index.astro` 与 `src/pages/blog/[...slug].astro`
- 非默认语言（有前缀）：`src/pages/[lang]/blog/index.astro` 与 `src/pages/[lang]/blog/[...slug].astro`

Header 中的语言切换使用 `src/i18n/routing.ts` 将当前路径改写为所选语言的路径。

## 6) 快速检查清单

- 文章文件位于 `src/content/blog/<slug>/<locale>.mdx`
- Frontmatter 包含 `title`, `description`, `pubDate`, `lang`
- 可选：`keywords`, `heroImage`, `updatedDate`
- 本地运行：
  - `bun run dev`
  - `bun run check`
