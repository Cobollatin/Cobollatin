# Security Policy

## Reporting Security Issues

The security of this project is taken very seriously. We appreciate your efforts to responsibly disclose your findings, and will make every effort to acknowledge your contributions.

If you discover a security vulnerability, please report it to us privately. **Do NOT report security vulnerabilities through public GitHub issues.**

Please email your report to `project-maintainers@example.com`.

When reporting a vulnerability, please include the following information:

*   **A clear description of the vulnerability**: Explain the nature of the vulnerability.
*   **Steps to reproduce**: Provide detailed steps that would allow us to reproduce the vulnerability.
*   **Potential impact**: Describe the potential impact of the vulnerability (e.g., data exposure, unauthorized access).
*   **Proof of Concept (PoC)**: If possible, include a PoC (code, screenshots, or a video) to demonstrate the vulnerability.
*   **Your name and affiliation (optional)**: If you wish to be credited for your discovery.

## Our Commitment

Upon receiving a security report, we are committed to the following:

1.  **Acknowledgement**: We will acknowledge receipt of your report within 48 hours.
2.  **Investigation**: We will investigate the reported vulnerability to confirm its validity and assess its impact. We may contact you for additional information during this process.
3.  **Resolution**: If the vulnerability is confirmed, we will work on a fix and determine a timeline for its release.
4.  **Disclosure**:
    *   We will coordinate with you on the public disclosure of the vulnerability. We aim to disclose vulnerabilities once a patch is available.
    *   We will credit you for your discovery, unless you prefer to remain anonymous.
    *   We may issue a security advisory (e.g., via GitHub Security Advisories) to inform users about the vulnerability and the steps to take.

We aim to handle security vulnerabilities in a timely and responsible manner.

## Scope

While we welcome reports for any part of our project, we are particularly interested in vulnerabilities in the following areas:

### In Scope

*   The main application code hosted in this repository.
*   The official website and services hosted on domains directly managed by the project.

### Out of Scope

*   Vulnerabilities in third-party services or dependencies that we use. Please report these to the respective service or dependency maintainers.
*   Issues that are already publicly known or have been previously reported.
*   Denial of Service (DoS) attacks that require significant computational resources, unless they demonstrate a critical flaw.
*   Social engineering attacks.
*   Physical security vulnerabilities.
*   Reports from automated vulnerability scanners without manual validation or a clear PoC.

If you are unsure whether a vulnerability is in scope, please report it to us, and we will assess it.

We appreciate your help in keeping our project secure.
